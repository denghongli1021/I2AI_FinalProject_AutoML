[HIGH] 1. 打字錯誤「匯名訪客模式」
  位置：index.html line 218
  問題：「匯名」應為「匿名」，出現在頂部 auth 區塊，評審一眼就看到。
  修法：將 "匯名訪客模式" 改為 "匿名訪客模式"。

------

[HIGH] 2. Real mode 下 AutoML Pipeline 頁面完全消失
  位置：index.html line 111，class="nav-item nav-mode-demo hidden"
  問題：Pipeline 觸發訓練的入口只在 Demo 模式下才出現，Real mode 使用者
        完全找不到如何開始訓練，整個核心流程（上傳 → 預處理 → 訓練 → 結果）
        在 Real mode 中斷了。評審在 real mode 測試時會以為功能不完整。
  修法：移除 nav-mode-demo 的 hidden 限制，Real mode 也要顯示 Pipeline，
        只是根據是否有 dataset 來決定 disabled / enabled 狀態。

------

[HIGH] 3. 「部署與 API」頁面被整個 comment 掉
  位置：index.html line 129-132（<!-- ... 部署與 API ... -->）
  問題：完成訓練、模型排名出來之後，使用者沒有部署出口。
        評審/老師會問「訓練完可以幹嘛？」但找不到答案。
  修法：取消 comment，加 disabled 樣式或「即將推出 / Coming Soon」badge，
        至少讓人知道這條路是存在的，比完全消失好太多。

[HIGH] 4. Demo / Real 模式切換體驗差，易造成誤解
  位置：index.html line 181-184，top bar 右側 #mode-badge
  問題：
    a. 按鈕很小、視覺層級低，初次使用者不知道「實作模式」是什麼意思。
    b. 切換後沒有任何 toast 或說明，UI 大幅變化（空頁面）讓人以為系統壞掉。
    c. 預設是 real mode，但後端可能還沒有資料，導致所有頁面都是空白 empty state。
  修法：
    a. 切換時顯示 toast："已切換至 Demo 模式，以下數據為示範用途"。
    b. 初次進入建議預設 demo mode，讓評審馬上看到效果。
    c. 在 mode badge 旁加一個 tooltip 說明兩種模式的差異。

  位置：new-ui/page-experiments.jsx line 34，progress: 0.5

[HIGH] 21. visualize.py 的核心 chart_type 未實作 (TODO 懸掛)
  位置：api/visualize/visualize.py line 31
  問題：以下 chart_type 尚未實作，請求會直接拋出 HTTP 400：
          - "residuals"       → 回歸任務必備，看模型殘差分佈
          - "confusion_matrix"→ 分類任務必備，評審必看
          - "shap"            → Insights 頁面的核心功能
        前端 Insights 頁面已有完整 UI 框架在等這些圖表資料，
        但後端缺位導致整個 Insights 頁面功能殘缺。
  修法（建議優先順序）：
    Step 1 - confusion_matrix：
      labels = sorted(set(testTrue))
      matrix = [[sum(1 for a,p in zip(testTrue,testPred) if a==t and p==pr)
                 for pr in labels] for t in labels]
      回傳 ECharts heatmap option
    Step 2 - residuals（回歸）：
      pairs = list(zip(testTrue, [a-p for a,p in zip(testTrue,testPred)]))
      回傳 ECharts scatter option
    Step 3 - shap：
      如果 backend 有存 SHAP values 就用，否則先回傳 feature_importance
      當作 fallback，並在 response 加一個 "fallback": true 的 flag。

[HIGH] 22. preprocess.py 只支援 CSV，但 UI 聲稱支援 TSV
  位置：api/preprocess/preprocess.py line 38
  問題：pd.read_csv(io.BytesIO(file_bytes)) 沒有指定 sep，
        pandas 預設 sep=',' 會讓 TSV 檔案全部塞在第一欄，
        但 index.html / new-ui 的 upload zone 都標榜「支援 CSV / TSV 格式」。
  修法：
    df = pd.read_csv(io.BytesIO(file_bytes), sep=None, engine='python')
    sep=None + engine='python' 讓 pandas 自動偵測分隔符（CSV/TSV/管道都能處理）。
    另外 file input 的 accept 屬性應加 .tsv：accept=".csv,.tsv,.txt"（舊介面已有，確認新介面也有）。

[HIGH] 23. 訓練模組沒有 cancel 機制
  位置：api/train/__init__.py，只 export run 和 run_prepared
  問題：訓練一旦觸發就無法中途取消，長時間（尤其 Neural Network 15m+）訓練
        會佔用 server 資源。使用者在 UI 上如果點了 cancel 也沒任何效果。
  修法：
    a. 短期：在 train.py 中用 multiprocessing 或 thread，訓練 run 存入全域
       dict，提供 cancel(run_id) 呼叫 process.terminate()。
    b. 長期：考慮用 Celery / BackgroundTasks + Redis，讓訓練任務可被 revoke。

[MID] 24. API cache 沒有明確 TTL 策略，可能顯示過期資料
  位置：new-ui/api-client.js（實作邏輯），多個 page 使用 getCached()
  問題：page-dashboard.jsx 的 cache 在 refreshTick > 0 時才 force refresh，
        但其他頁面（page-models.jsx）只在 mount 時拉一次，沒有 TTL。
        訓練完成後切回 models 頁，顯示的可能還是舊資料。
  修法：
    a. 訓練完成後，所有相關 API path 應一起 invalidate：
       NewUI.api.invalidate('/api/models')
       NewUI.api.invalidate('/api/training-runs')
    b. 或為 cache entry 加 ttl: 60000 ms，超時自動 refetch。

[MID] 25. preprocess.py 沒有檔案大小限制
  位置：api/preprocess/preprocess.py
  問題：直接把整個 file_bytes 讀進 pandas，
        如果上傳一個 500MB 的大 CSV，server 會 OOM。
  修法：
    MAX_BYTES = 50 * 1024 * 1024  # 50 MB
    if len(file_bytes) > MAX_BYTES:
        raise HTTPException(status_code=413, detail="檔案過大，上限 50 MB")
    同時在前端 upload handler 也做一層 client-side 檢查，提早報錯。

[MID] 26. train.py 沒有針對不同任務類型做欄位驗證
  位置：api/train/__init__.py，run() 和 run_prepared()
  問題：如果 target 欄位全是 NaN、或只有一個唯一值（e.g. 全部 churn=0），
        模型訓練會成功但結果毫無意義。
  修法：在訓練開始前加前置檢查：
    - target 欄位不能有超過 X% 的 NaN
    - 分類任務至少要有 2 個 class
    - 樣本數不能少於 N（建議 50 筆）
    檢查失敗時拋出明確的錯誤訊息回前端。

[LOW] 27. visualize.py 的圖表 textStyle color 是 hardcoded
  位置：api/visualize/visualize.py line 51，textStyle: {"color": "#e2e8f0"}

        圖表文字顏色就會不搭。
  修法：前端 call visualize API 時帶上 options.theme（"dark"/"light"），
        後端根據 theme 決定 textStyle 的 color 值。
